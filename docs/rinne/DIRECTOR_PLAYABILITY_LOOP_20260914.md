## ディレクター受入条件

1. 390×844のスマートフォン相当表示で、出生から歩行、生活行動、休息、地図、技・装備、前線、救助、帰村まで主要ループを通常入力で進められる。
2. プレイヤーが「今なにをするか」「次にどこへ行くか」「行動すると何が変わったか」を画面から判断できる。説明文だけで操作対象を探させない。
3. 移動・休息・生活行動・戦闘・メニュー中の状態が矛盾しない。メニューや手帳を閉じた後は、元のsolo停止状態を尊重して入力へ復帰する。
4. 主操作と戦闘/生活フィードバックが互いを遮らない。タッチ対象は原則44px以上で、画面中央の移動領域を確保する。
5. 成長・生活経験・技発見・前線突破・救助・転生の変化が、少なくとも次の判断に必要な範囲で直後に伝わる。
6. 保存再開、MURA配置更新、既存技/装備継承を壊さない。
7. 実ブラウザ回帰はテスト専用のゲーム状態setterやforce clickで成功させない。必要な長寿命シナリオのfixture読込は保存Envelope経由に限定する。
8. 「十分」の終了条件は、主要ループを再操作して新しいP0/P1の操作停止・意味不明な導線・状態不整合が見つからず、残りがコンテンツ拡張/審美調整として別フェーズに切り分けられること。

## 今回見つけて直した点

- DOM追加順に依存していた主行動を、現在の意図に沿って優先する。生活行動中の中断、受取待ちの閃き、救助、前線進行、帰還/出航を、一般的な周辺行動より上に出す。可否判定そのものは既存controllerを正本とする。
- 生活行動中や閃き待ちの短期目標を上部の目的表示へ反映し、「今の行動」「受け取れる報酬」を見失いにくくする。
- 同じ焚き火座標へfallbackしている複数の生活施設を地図上で別施設のように重複表示せず、一つの目的地へまとめて可能な行動を列挙する。既存`garden` IDをcanonicalとして保存・導線互換を維持する。
- 主人公の視認性改善として建物の自動透過も試したが、実画面レビューで景観への副作用が大きいと判断し採用しなかった。world geometry、当たり判定、配置、描画materialは最終製品差分で変更しない。
