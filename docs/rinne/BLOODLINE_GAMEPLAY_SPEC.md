## ゲームの一巡

初代の名前・種族を準備 → 0歳で出生 → 母の腕の中で移動・会話・小物の受取り → 自立 → 村で生活・学習・装備 → 接触戦闘 → 船で最前線 → 帰還または死 → 遺す技の選択 → 系譜に記録 → 過去の経験を1つ選ぶ → 次代の出生。

負傷による行動不能は死亡と別。戦いで倒れても、救助・休養から現世へ復帰できる。魔王を倒した後には帰還導線がある。村に留まって生活する選択も可能で、出生直後から強制出撃させる構造ではない。

## 輪廻転焦との重要な差分

**ユーザー確認済み：現行の輪廻転焦を優先する。** 90歳、60秒/年、時計だけ1〜20倍、現行Tidebreakの入力・戦闘・技と装備設定の全保持を維持する。加えて、MURAAAAAAAと魔王軍アプリが将来同じ世界を共有し、継続的な改良を取り込める構成とする。

| 論点 | 血脈の系譜の抽出値 | 輪廻転焦の現状 | 必要な判断 |
| --- | --- | --- | --- |
| 寿命 | 80〜100歳 | 90歳。LifeClockとMasterCharacterの両方が90歳まで | 本編も90歳に統一するか、可変寿命へ変更するか。可変化は表示だけの変更では済まない |
| 幼少期 | 約30秒で4歳へ解放 | 60秒で1歳、0歳開始 | 導入だけ時間圧縮するか、現在の時計に合わせた導入にするか |
| 時間速度 | debugのworld speedはSimulation全体へ適用 | 1〜20倍の速度設定は年齢・世界時計のみ。戦闘やモーションは加速しない | 別のSimulation時計をそのまま追加せず、時間倍率の対象を決める |
| 死後に残るもの | 選んだ1技を経験として残し、新しい人生で再学習 | 現行寿命ダイアログは技・装備設定を次の人生にも保持 | 本編の継承ルールを切り替えるか。稽古用設定と本編で所持する能力を分ける必要がある |
| 移動・戦闘 | タップ目的地移動、フリック持続ダッシュ、接触自動戦闘、各段5技 | Tidebreakの既存入力・技構成・戦闘を使用 | 本編でも現行操作を優先するか。旧操作を混ぜた認識器を追加しない |
| 父母と血縁 | 母の導入と世代履歴。父母IDの確定ルールは未確認 | MasterCharacterには2親から外見遺伝するデータ契約がある | 実在する親の決定・出生条件・系図は新しい本編仕様として決める。母演出から捏造しない |
| 種族 | 4種族の選択がある | 現行Shino基盤の外見・量産契約 | 元モデルを移植せず、どの種族を実際に表現可能か確認。名前だけで別種族の完成扱いにしない |
| 世界・ネットワーク | 元の村・船・前線・オンライン接続の契約 | 共有world、独立village/demon、招待・同期基盤 | 本編の世界だけを実装し、実プレイヤーの村との自動接続を付けない |

差分の基本案は「輪廻転焦の既存時計・モデル・操作・戦闘を基準にし、母の導入・生活経験・救助・世代履歴を新しく組み込む」。採用差分は現行優先で確定した。上表の旧「必要な判断」は比較の記録であり、寿命・操作・継承の承認待ちを意味しない。

## 独自実装の構成

| 単位 | 主な責務 | 接続・維持する既存基盤 |
| --- | --- | --- |
| 本編セッション | 同じ人生の再開、出生、死亡、継承選択、次代開始を一貫して管理 | `apps/rinne/src/game/` に新規。DOM/storageを入れずPlatform portsを注入 |

| 負傷・救助 | 行動不能と死亡の区別、運搬、回復、トドメ | 現行戦闘の結果を明示イベントで受ける。二重ダメージ判定を作らない |
| 世代履歴 | 生涯の確定記録、提供者・経験の参照、選択と再検証 | MasterCharacterの個体IDと外見。血縁と経験提供者を別フィールドにする |
| 世界進行 | 村の生活→出港→前線→帰還 | `packages/world` の公開契約。村・魔物アプリの状態を直接書き換えない |
| Web画面 | 本編開始・再開、系譜、生活の表示と入力 | 既存のタイトル・読込進捗・再試行・戻る・音楽・中断処理 |
| 保存 | 世界と生涯の整合、失敗と復元、schema migration | 環境・ゲーム・プレイヤー別の保存。既存Tidebreak保存を上書きしない |

元の巨大Simulation、prototype差し替え、描画ループ、サーバーengine群を持ち込まない。モジュールを独自実装し、元の数値や条件は採用が決まったものだけをゲームデータとして持つ。衣装・技モーション・描画の改造は、本編ルールを組み込む変更と分離する。

### 実装順序と完了判定

1. **人生と系譜**: 初代→進行保存→再開→死亡→遺す経験→次代を一巡させる。選択未完了、無候補、未知ID、重複クリック、再読込を検証。時計・継承ルールの採用判断が必要。
2. **母と村の生活**: 抱っこ→小物取得→解放→移動→施設活動→7歳の装備を実操作で確認。生活イベントが実際の経験へ反映されることを確認。
3. **習得と戦闘・救助**: 新規習得が既存配分を変えず、負傷→運搬→復帰、後続攻撃による死亡まで接続。元技と輪廻転焦側の技の対応を確定。
4. **遠征と帰還**: 乗船条件、出港の一意性、前線進行、帰還、途中死亡・中断復帰。実プレイヤー接続の代替としてローカル成功を報告しない。

各段階は進捗であり、1段階だけで「本編完成」とは報告しない。PRの受入対象を明示し、局所検証後にReady化する。CI監視・develop統合・DEV反映は現在のIntegrationへ渡し、main / Productionは変更しない。

## 最低限の受入シナリオ

- 初回に履歴を捏造しない。生存中の再開・履歴閲覧から戻る操作で、別人生を生成しない。
- 入力ロックを残さず抱っこから解放。容量2点の境界、捨てる、再取得、贈り物の由来を確認。
- 6歳では装備拒否、7歳で条件付き許可。見た目だけ隠して装備済み扱いにしない。
- 非表示・一時停止の扱いを既存時計と一致させ、世界速度を二重適用しない。
- 世代の記録は一度だけ。保存後再読込・同じ死亡イベントの再送でも重複しない。
- 遺す技／継ぐ経験の確定を分離。未知・削除済みIDや未選択状態から不正に出生しない。
- 傷・行動不能・死亡を区別。転倒させた一撃で同時にトドメを処理しない。
- 運搬者と対象の片方だけが状態遷移しない。失敗・中断・死亡時の相互参照を解放する。
- 原本のHTML、JS、shader、model、audio、セーブを持ち込んでいないことをdiffで確認。
- 既存のタイトル→稽古→タイトル、Character Workshop、村・魔物アプリが引き続き動作する。
- 保存失敗を通知し、以前の記録を無言で消さない。モバイルでは影響する操作を局所確認する。
