# 輪廻転焦 本編プレイスルーUX

現行 `apps/rinne/src/rebuild/` を本編の操作正本とし、初見プレイヤーが外部説明なしで一生を進められることを受入条件にする。

## 基本ループ

1. 出生。母と村を歩き、4歳までに移動・会話と村の存在を知る。
2. 村で成長。暮らしの場所を巡り、経験・技・武具を知る。
3. 7歳以降に武具を選び、15歳以降の出航条件と港を理解する。
4. 港から前線へ出立。敵に接近すると自動戦闘になることを画面内で理解する。
5. 前線を突破し、さらに奥へ進む。最終前線では帰還地点を明示する。
6. 行動不能なら救助で村へ戻る。突破できれば凱旋して村で次の出航を待つ。
7. 寿命を迎えたら生涯の記録を確認し、記憶を選んで次の自分へ転生する。

## UI受入条件

- 常時HUDは「現在の段階・短い目的・方向/距離」を中心にし、説明文を常設しない。
- 生活行動・装備変更・出航・戦闘など、近接や停止で自動発火できる行動にはコンテキストボタンを追加しない。原因と結果は短い状態表示・トースト・演出で伝える。
- コンテキストボタンは自動化できない任意操作だけに限定する。現行rebuildでは実際に画面上へ存在する会話相手は出生時の母だけなので、通常生活ではボタン0個、出生中だけ「話す」を表示する。将来NPC会話を増やす場合も、対象NPCが実際に近接している時だけ出す。
- 不可逆な選択や明示確認が必要な場面は個別UIで扱い、転生などは明示ボタンを維持する。
- 年齢や条件の解禁は長文で説明せず、必要な時だけ短いロック/年齢表示や目的の変化で示す。
- 目的地がある場合は方向と距離を表示する。目的地付近で自動発火する行動はボタンではなく、短い動詞または状態名で予告する。
- 年齢待ちだけの時間を作らず、待機中は村の目的地を示す。操作説明は初回・状態変化時の短い表示に留める。
- 前線は「敵 → 奥 → 帰還」の方向を画面から読み取れる。攻撃ボタンは置かず、敵への接近で自動戦闘する現行仕様を維持する。
- 行動不能時は救助までの残りを簡潔に示し、救助・帰還そのものにボタンを要求しない。
- 100歳時は転生がゲームループの続きであることを示し、継承内容を確認できる。転生のような不可逆な選択は明示ボタンを維持する。
- 390x844相当の縦画面で主要情報が重ならず、中央のプレイ領域を塞がない。

## 世界観表現

輪廻転焦のUIはWeb管理画面ではなく、中世ファンタジー世界の「紋章・金属・革・羊皮紙・刻印」を現代的に整理したゲームHUDとして扱う。HTML/CSSのカード感、無地の半透明パネル、業務UI風のラベル群を主役にしない。

- タイトルは黒緑の背景に文字を並べるだけでなく、紋章・薄い放射紋・古紙/煤の質感・章扉の構図を持たせる。
- 常時HUDは一枚のカードではなく、左上の系譜章、生命/息の細い刻印ゲージ、右側の小さな目的札、画面中央の方向標という役割分離にする。
- 枠は四隅の角金具、細い金属線、擦れた真鍮、暗い革の面で構成し、角丸カードと均一なガラス面を避ける。
- 状態変化は説明文ではなく、紋章の発光、短い章題、ゲージの瞬間発光、画面端の薄いビネット、短いトーストで伝える。
- 村は暖色寄りの真鍮/革、前線は鉄・灰・赤錆、輪廻は白金・淡い金へトーンを変え、同じHUDでも人生の場所が変わったことを感じさせる。
- 目的地矢印はナビアプリ風の丸アイコンではなく、方位針・刻印・小さな旗標を想起させる造形にする。
- UI装飾は視界を奪わない。中央の3Dプレイ領域を空け、周辺視で読める情報量に留める。

### 公開実装から採用する構造

- Mozilla `BrowserQuest` の羊皮紙・装飾フレーム・ゲーム画面に密着したステータス帯という「世界観をUI素材へ持ち込む」考え方を参照する。BrowserQuestのコードはMPL 2.0、コンテンツはCC-BY-SA 3.0なので、画像・CSS・文言は持ち込まず構造だけを参考にする。
- MITの `elberacasa/claudeage` のHUD実装から、WebGLの上にDOM HUDを重ねる分離、角飾り、細い金縁、ダメージ時ビネット、状態変化を数値以外でも読ませる設計を参照する。第三者アセットは持ち込まない。
- `NikLever/THREEjs_RPG_Game` はThree.js上へ必要な円形操作だけを置く実装例として参照するが、明示ライセンスを確認できないためコードや資産は転用しない。

## 検証

ドメインテストに加えて、Playwrightでタイトル → 新生 → 村生活 → 武具 → 出航 → 前線 → 凱旋/救助 → 寿命 → 転生の主要導線を実UI経由で通す。保存データの直接注入は長時間待機を短縮する補助に限定し、目的表示・操作可能性・遷移結果は実画面で確認する。

追加で、生活・装備・出航・戦闘に専用のコンテキストボタンが増えていないこと、出生終了後に会話ボタンが常駐しないこと、通常HUDに長い説明文を置かないことをブラウザ検証する。さらに、角飾り/素材トーン/章題演出がDOM上に存在し、前線・村・輪廻でHUDのトーンが切り替わることをUIテストで固定する。
