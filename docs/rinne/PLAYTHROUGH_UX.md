# 輪廻転焦 本編プレイスルーUX

現行 `apps/rinne/src/rebuild/` を本編の操作正本とし、初見プレイヤーが外部説明なしで一生を進められることを受入条件にする。

## 基本ループ

1. 出生。母と村を歩き、4歳までに移動・会話と村の存在を知る。
2. 村で成長。暮らしの場所を巡り、経験・技・武具を知る。
3. 7歳以降に武具を選び、15歳以降の出航条件と港を理解する。
4. 港から前線へ出立。敵に接近すると自動戦闘になることを画面内で理解する。
5. 前線を突破し、さらに奥へ進む。最終前線では帰還地点を明示する。
6. 行動不能なら救助で村へ戻る。突破できれば凱旋して村で次の出航を待つ。
7. 寿命を迎えたら生涯の記録を確認し、次の出生先を選んで次の自分へ転生する。

## UI受入条件

- 常時HUDは「現在の段階・短い目的・方向/距離」を中心にし、説明文を常設しない。
- 生活行動・装備変更・出航・戦闘など、近接や停止で自動発火できる行動にはコンテキストボタンを追加しない。原因と結果は短い状態表示・トースト・演出で伝える。
- コンテキストボタンは自動化できない任意操作だけに限定する。現行rebuildでは実際に画面上へ存在する会話相手は出生時の母だけなので、通常生活ではボタン0個、出生中だけ「話す」を表示する。将来NPC会話を増やす場合も、対象NPCが実際に近接している時だけ出す。
- 不可逆な選択や明示確認が必要な場面は個別UIで扱い、転生などは明示ボタンを維持する。
- 年齢や条件の解禁は長文で説明せず、必要な時だけ短いロック/年齢表示や目的の変化で示す。
- 目的地がある場合は方向と距離を表示する。目的地付近で自動発火する行動はボタンではなく、短い動詞または状態名で予告する。
- 年齢待ちだけの時間を作らず、待機中は村の目的地を示す。操作説明は初回・状態変化時の短い表示に留める。
- 前線は「敵 → 奥 → 帰還」の方向を画面から読み取れる。攻撃ボタンは置かず、敵への接近で自動戦闘する現行仕様を維持する。
- 行動不能時は救助までの残りを簡潔に示し、救助・帰還そのものにボタンを要求しない。
- 100歳時は転生がゲームループの続きであることを示し、次の出生先と継承範囲を確認できる。転生のような不可逆な選択は明示ボタンを維持する。
- 390x844相当の縦画面で主要情報が重ならず、中央のプレイ領域を塞がない。

## 起動契約

輪廻転焦は「タイトルを先に見せ、開始ボタンを押してからThree.jsと村を生成する」構造にしない。尽喰廻遊と同じく、ページ読込時に描画系と世界を一度だけbootし、準備完了後にタイトルを表示する。

- 初回ページ読込ではタイトルをまだ表示せず、軽量なローディング画面を先に描画する。
- runtime module、Platform、村レイアウト、Three.js renderer、村モデル、主人公/母の描画資源までを初回bootで準備する。
- boot完了後にタイトルを表示する。タイトル表示時点でrenderer/worldは再利用可能なstandby状態であること。
- 「新しい人生」「つづきから」はrenderer/worldを生成しない。既存runtimeへ新しいlife stateまたは保存stateを束縛して即座にゲーム面へ切り替えるだけにする。
- タイトルへ戻ってもrenderer/worldを破棄しない。人生セッションだけ停止・保存し、次回開始で同じ描画資源を再利用する。
- WebGL/context破棄はページ終了・HMR等のruntime終了時だけ行う。
- 初回boot中は「村の地図」「景色」「旅人」など短い進行表示を更新し、ブラウザへ描画権を返す。
- boot失敗時はエラー内容と再試行をローディング画面へ出し、無反応のまま残さない。

## 世界観表現

輪廻転焦のUIはフラットデザインへ戻さない。一方で、玩具・キャンディ・幼児向け絵本のような高彩度ポップにも寄せない。目標は「カジュアルに遊べる中世ファンタジー」で、軽快さと世界観の品を両立する。

- 色はアイボリー、砂金色、くすんだ空色、落ち着いたコーラル、青紫を中心にし、同一画面で使う強いアクセント色は2〜3色までに絞る。全面を虹色にしない。
- 背景は黒緑へ戻さず、明るい空・紙・石・革を感じる低彩度の暖色/寒色で構成する。自然物としての緑は残してよいが、UI全体の基調にはしない。
- タイトルは「朝の旅立ち」を感じる明るさを維持しつつ、虹色の大きな円やキャンディ色の装飾を主役にしない。紋章、細い金属線、淡い放射紋、布/紙の質感を少量使う。
- ボタンはフラットにせず、1〜3px程度の縁、控えめな上面ハイライト、2〜4px程度の底面/落ち影、押下時の沈み込みを残す。丸みは中程度に抑え、すべてを大きな丸角やピル形にしない。
- HUDはクリーム/革色の小さなプレート、細い金属縁、色付きの小アクセントで構成する。宝石・リボン・丸いバッジを多用せず、情報階層を形と余白で作る。
- 命/息ゲージは槽の立体感を残す。命は落ち着いた朱〜赤、息はくすんだ水色〜青。強い光沢やネオン発色は避ける。
- 村は蜂蜜色/空色/革色、前線は灰紫/錆赤/琥珀、凱旋は淡金、輪廻は白/淡藤へ切り替える。状態差は読めるが、画面全体を強く染めない。
- 章題、会話、100歳/転生画面は同じ素材言語で統一し、子供向けUIのような太い白縁・大きなドロップシャドウ・跳ねる装飾を抑える。
- フォント、余白、線の太さ、アイコン寸法を揃え、装飾よりタイポグラフィと構図でスタイリッシュさを出す。
- 起動ローディングも同じ方針に合わせる。アニメーションは残すが、多色スピナーや跳ねるドットは抑え、紋章/輪の静かな回転と短い進行表示を主役にする。
- 装飾は軽量なCSSを優先し、ゲーム本体のWebGL描画やモバイル性能を犠牲にしない。

## 検証

ドメインテストに加えて、Playwrightでタイトル → 新生 → 村生活 → 武具 → 出航 → 前線 → 凱旋/救助 → 寿命 → 転生の主要導線を実UI経由で通す。保存データの直接注入は長時間待機を短縮する補助に限定し、目的表示・操作可能性・遷移結果は実画面で確認する。

追加で、生活・装備・出航・戦闘に専用のコンテキストボタンが増えていないこと、出生終了後に会話ボタンが常駐しないこと、通常HUDに長い説明文を置かないことをブラウザ検証する。さらに、ページ読込時にruntime/worldのprebootが完了してからタイトルを出すこと、開始クリック時にrenderer/worldを再生成しないこと、タイトル復帰後も同じpreboot資源を再利用できることを固定する。UIテストでは非フラット、非緑基調、低彩度、限定アクセント、過大な丸角/多色装飾の不使用を受入条件にする。
