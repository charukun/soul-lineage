# 百年転生本編と共有世界

タイトルの「本編をはじめる・つづける」から出生、村生活、前線、救助、寿命、転生までを進行する。稽古用スキルシミュレーターは従来の入口と保存を維持する。血脈の系譜からは挙動だけを抽出し、そのコード・アセット・データは取り込まない。

## 現行優先

時計は本編の一つの人生時計だけを使用する。0歳開始、60秒/年、**100歳で生涯終了**。1 / 5 / 10 / 20倍は世界時計だけで、移動・戦闘・生活行動の実秒を加速しない。転生すると年齢・体力・傷・装備・所持品・序破急/心得/構えの編成・その生涯の経験記録は基礎状態へ戻り、**一族の記録と、実際に帰還して刻んだ故郷だけを次代へ残す**。UIは転生確定前にこの「残るもの / 手放すもの」を実挙動と同じ契約から表示する。

戦技の発見・未確認バッジによる能力解禁UIは現行では使用しない。心・技・体で選択可能な候補はUIが独自生成せず、ゲーム側の combat catalog を参照する。現時点のcatalogは既存の戦技候補を利用可能として始めるが、将来catalogを絞る場合もUI側の直書きで迂回しない。生活経験は人生の記録と案内に残し、能力解禁を装わない。

本編の人生・戦闘ルールは `apps/rinne/src/rebuild/` とそのゲーム側contractを正本とし、表示adapterはその結果だけを描画する。既存Tidebreakの入力・自動戦闘を再実装せず、その描画とループを使用する。製品UIからQA用APIやDEBUG専用操作を呼ばない。

## 宝満叡智を共通の参照元にする

| 所有先 | 共通部分 | 更新時の扱い |
| --- | --- | --- |
| `@soul/world/mura` | 地形ID、メートル座標、川・渡河点、敷地判定、建物・家具カタログ、初期3施設、配置の検証 | 地形・カタログ変更はここへ。村側の旧importは再exportで互換維持 |
| `@soul/rendering/mura` | 現行Kenney形状、建物・家具・自然物、MURA地形描画 | Threeとcanvas生成を注入し、同じ表示モジュールを使う。原本形状と出典を保持 |
| `@soul/platform-web/shared-world` | 同じ端末・origin・environmentでの配置publish/read/subscribe | 村だけがpublish。読み手から村の保存を上書きするAPIを提供しない |
| `apps/village` | 建築、増築、住人の仕事、資材、村長・UI、保存の正本 | 保存成功後に建物・家具配置だけを投影してpublish |
| `apps/rinne` | 人生、生活経験、技、体力、持ち物、遠征 | 最新の同じ村IDの配置を受け取り、人物進行を維持 |
| `apps/demon` | 狩り、敵側進行、入村履歴・報酬 | 既存仕様を維持。同じ共通world契約を使用できる。既存の襲撃マップをこのPRで自動置換しない |

固定した宝満叡智のコピーを百年転生の中に置かない。宝満叡智の改良のうち、共通景観・建物カタログ・地形に関するものは上記共有モジュールへ反映する。村長UIやゲーム固有の演出は各appに残す。共有packageの変更は依存グラフにより3アプリの影響対象になる。

配置は `schemaVersion / id / terrainId / revision / units / coordinateSystem / objects`。entity IDを改築・移動で再採番しない。室内家具のIDと相対座標も保持する。資材、住人の私的状態、認証情報、プレイヤー能力、魔王軍の入村台帳は配置へ混ぜない。未知のschemaやkindは受け付けず、手元の動作中マップを維持して更新保留を表示する。

本編は同じ端末で宝満叡智を開いた後、その配置を使用する。未作成ならMURAの現行初期地形と3施設を使用する。建設前の学校・治療所等の生活行動は焚き火周辺で行い、建築後は該当施設入口へ移る。母の導入は住居入口。武具は護衛テント/武器屋、出航は港/東海岸。物理配置を別の縮尺へ変換しない。

共通配置の保存は実プレイヤーが同じサーバーで動いていることを意味しない。本編の記録画面から村の書き出しJSONも読み込める。明示読込は本編用の読み取りスナップショットを保持し、村の元保存を変更しない。同じIDの更新は自動反映、別IDの村は勝手に切り替えない。建築位置がプレイヤーに重なった場合は近くの歩ける土地へ移す。

## 保存と進行

### 生活から次の戦いまでの受入条件

村での生活行動、経験の蓄積、戦技の編成、装備の入手と身支度、戦闘での使用、帰還後の支度を通常の操作で一巡できること。次の目的・場所・方向・距離・年齢と出航条件を画面から確認できる。生活経験は「この生涯で何をしてきたか」の記録として参照でき、能力解禁が無効な現行contractで未習得・閃き済みを装わない。

0歳開始・60秒/年・100歳の生涯・武具7歳・遠征15歳・5世界年ごとの出航・生活行動8実秒を維持する。世界時計の速さはsoloで 1 / 5 / 10 / 20倍から明示的に選び、移動・戦闘・生活行動の実秒へ倍率を掛けない。sharedでは本人のUIから世界時計を変更できず、無効理由を短く表示する。

装備変更はUIから `state.equipment` を直接書き換えない。7歳以上・living・村内・非戦闘・行動可能・武具置き場の近接・所持済みをゲーム側commandで再検証し、UIは成功結果または短い失敗理由だけを表示する。武具の取得と装備変更は別の出来事として扱う。

戦技候補はゲーム側の combat catalog を表示adapterへ渡す。心・技・体の画面はcatalog外の候補を生成しない。序破急の編成値は既存保存との互換を維持し、通常戦闘HUDでは現在の序 / 破 / 急だけを小さな共通部品で表示する。通常攻撃ボタンは追加せず、敵への接近で自動戦闘へ入る現行仕様を維持する。

目的案内と地図は同じ guidance target ID / 座標を参照する。常時HUDは段階・短い目的・方向/距離を表示し、地図は現在位置と同じ目的地を強調する。UI都合で地形やプレイヤー座標を変更しない。障害物を考慮した正式経路が得られない場合、直線案内を「経路」と偽らず目的方位として表示する。

本編の保存はenvironment別の一つのenvelopeに、人生・時計・体力/位置・遭遇中の敵・戦技編成・参照中の村配置をまとめる。保存を検証してから復元し、壊れたデータを新しい人生で上書きしない。参照配置は再開用のスナップショットであり、建物モデルや地形コードを固定しない。村の最新配置があれば読み替える。

Web Locksで本編の同時書き込みを防ぐ。別タブで同じ本編が開いている場合は再開を止める。排他制御がない環境では自動保存せず、書き出しで保管する。保存不可は画面へ表示し、通常の保存書き出し/読み込みも提供する。

途中の戦闘動作・音・VFXは再開時にリセットするが、敵の体力/戦闘不能と人生進行を復元する。隠れた画面、一時停止、世界設定、記録画面では人生を進めない。ソロでは戦技編集・地図・記録・視点メニューの間も停止し、閉じると元の停止状態へ戻す。共有世界では本人の入力だけを切り替え、世界時計を止めない。

## 次の共有セッション接続で守る境界

現在の `read/subscribe` を、村長ホストの検証済み配置snapshotへ接続する。ホストepoch・revision順序・認証と認可はその既存ネットワーク層で扱う。localStorageをネットワーク権限の正本にしない。村の住人と百年転生の本人、魔王軍の本人を同一人物と仮定しない。村の時間単位と百年転生の年齢を暗黙変換せず、共通ホスト時計への変換は後続の同期契約で決める。

本PRはこの境界とローカルの配置連動まで。認証済み同時対戦・報酬確定・ホスト移行の完成は主張しない。既存魔王軍の入村履歴と認可を本編の転生や村改築でリセットしてはならない。

## 検証入口

- `node scripts/validate.mjs fast origin/develop HEAD`：影響app/packageの構文・境界・domainテスト・build。
- `node apps/rinne/tests/story-browser.mjs`：出生、生活、再開、別タブからの配置更新、前線、救助、寿命、転生、縦画面、従来シミュレーター。独立した局所ブラウザ確認でありfast gateには含めない。
- `node apps/rinne/tests/page-ui-browser.mjs`：縦横3サイズで心・技・体・装、マップレーダー/詳細地図、記録の全ページ、閉じた後の入力復帰を確認する。fast gateとは別の局所確認。
- `CHROMIUM_EXECUTABLE` で検証用ブラウザを指定できる。SwiftShaderの画面結果をスマートフォン実機FPS保証としない。

Kenney形状の従来の出典は `apps/village/docs/ASSET_PROVENANCE.json`。本編配信にも `public/licenses/` の出典と利用条件を同梱する。

## 本編UI・操作の受入条件

本編はフラットなWeb管理画面の構成を使用しない。彫金・革・羊皮紙の質感、段差、陰影、押下状態を持つゲームHUDを維持する。タイトル、常時HUD、会話・行動、戦技、身支度、地図、記録、転生を一貫した画面体系で扱う。

- 縦持ちスマートフォンでは、中央の視界と移動領域を常時確保する。情報窓を重ねて移動を遮らない。
- 主なタップ対象は44px以上。近接行動を優先し、武具一覧や生活行動を常時すべて並べない。
- 常時HUDは年齢/世代、命/息、短い目的、方向/距離を中心にする。説明文を常設しない。
- 下部の常設入口は「心 / 技 / 体 / 装」を基本とし、心・技・体を独立した主要操作として扱う。地図は下部ボタンへ置かず、画面右上の常設マップレーダーから開く。記録はレーダー/プレイヤー情報と競合しない補助入口へ移す。製品UIへDEBUG専用入口を置かない。
- 移動中・停止中・休息中・一時停止中を区別し、移動方法と次の目的地が画面から分かる。既存スワイプ・フリック・自動戦闘のルールを維持する。
- 戦闘中だけ序 / 破 / 急の現在段を表示し、非戦闘時は中央視界から消す。
- 画面右上のマップレーダーから現在位置・進行方向・主要施設・現在の目的地を常時簡潔に確認でき、タップで詳細地図を開ける。詳細地図は地形・施設種別・目的地・現在地・方位・距離の関係が読めるリッチな表示にする。HUD、レーダー、詳細地図は同じtarget IDを使い、世界の建物IDやMURA地形をUI都合で作り直さない。
- 行動不能時は救助残秒を目的表示の主情報とし、手動救助ボタンを要求しない。
- 生存中の「記」から系譜を閲覧しても、転生や継承確定を発生させない。
- 転生は「生涯記録 → 残るもの/手放すもの → 出生先」の確認を通り、最後の明示決定だけが次代を開始する。
- メニューを開閉した後の入力復帰、実移動、会話・生活行動、装備、戦闘、保存再開を局所の実ブラウザ操作で確認する。

### スクロールを原則使わない画面設計

本編と稽古場の通常操作は、縦横ともスクロールを前提にしない。長い設定・一覧は目的別のタブや前後のページへ分け、閉じる・戻る・決定を画面内の固定位置へ置く。スクロールバーを隠して内容を切り捨てる対応や、文字・タップ領域を縮めて押し込む対応は禁止する。

- 心 / 技 / 体 / 装は同じ基本骨格を使い、上段を原則1行3列の選択スロット、下段を関連する習得済み要素の5列グリッドとする。候補が多い場合は固定件数ごとの前後ページで全件へ到達できる。
- 地図・行き先・人生の記録・系譜もページ切り替えで完結する。記録件数が増えても全世代へ到達できる。
- 360×640、390×844、横持ち844×390で、表示中の通常画面と主要操作が画面内に収まり、ページの開閉後も移動できることを確認する。
- ソフトキーボード、拡大文字、非常に小さい画面では、操作不能を避けるために必要な最小領域だけスクロールを認める。ゲーム内文書など長文はページ送りを優先する。

ページ割りは表示adapterの責務とし、前後ボタンとページ表示を固定位置に置く。UIのページ化のためにゲームルール・保存値・MURAの地図データ契約を変更しない。

### マルチプレイを前提にしたUIの権限

本編の現行セッションは明示的にsolo。メニュー用の入力遮断と世界時計の一時停止を分離する。soloではメニューを閉じるまで時を止める。sharedでは自分の移動入力だけを遮断し、時計・戦闘・他プレイヤーを止めない。既存authorityのopen / migrating / closedを表示に受け、移行中・切断時はローカル指示を停止する。UIがhost選出、epoch/revision更新、checkpoint公開を実行してはならない。

共有セッションではローカル時計操作・保存の置換・村配置の手動取込を無効にする。旅人一覧は接続adapterが提供した安定player IDと接続状態を使い、NPCや別タブをオンライン参加者に見立てない。地図も現行MURAのentity IDと配置を参照する。

`menu-gate.js`は上記の入力・一時停止契約を独立検証する。`__RINNE_GAME_PORT__.session()`の現行実装はsolo固定であり、UIからオンラインへ切り替える偽設定は用意しない。本編への認証済み共有session接続は引き続き後続工程。タイトルの既存「村へ参加」の接続実装と、本編のローカル進行を同じsessionだとは扱わない。
