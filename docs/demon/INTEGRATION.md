# 暗い喰らいCry — DEV統合

入力は `Kurai_Night_Hunt_v2_Source.zip`。開始時の実装正本は develop `6e8c1dc669feba109fa1ee7b3fa026152921b38f`。この時点の輪廻転焦・村は共通家具を表示する雛形であり、Tidebreak本編・ハウジングエディター・認証・実対戦サービスはdevelopにありませんでした。別WORKの未commitファイルを正本として取り込みません。後続の運用基盤変更 `ab33196` へ追従し、最新の高速PR/最終Integrationフローを保持しました。

## 実装済み

- `/dev/demon/` でThree.jsの狩場を実行。タップでは移動せず、スワイプ移動・短いフリックの継続走行・接敵時の走行停止。
- 序破急・間合い・被弾・勝敗はZIPのTidebreak互換エンジン。独自の簡略ダメージ計算へ置換していません。
- 人間NPCの捕食、記憶3枠、形態変化、警鐘、討伐騎士、帰還・撤退・敗北。NPCを実プレイヤーと表示しません。
- ハウジング保存JSONの配置を襲撃用に読込。元データを書き換えず、村IDと所有者の旧形式IDを維持。改築・名前変更・revision更新は再入場券になりません。
- 入村前に履歴を書込。撤退・敗北・中断後も保持し、破損・容量不足時は入村停止。
- Web Locksで保存プロファイルの全更新を単一タブに限定。装備変更や捕食報酬で別タブの入村履歴が上書きされる競合も防止。Web Locksを利用できなければ明示的に停止。
- 保存はenvironment / demonで分離。ローカルreviewはさらに別領域。公開buildに状態変更用review hookは含めません。
- 起動モジュール取得、初期化、描画中断のエラー表示と再試行。再試行で入村履歴は削除しません。
- GitHub由来KayKit 2素材・加工記録・CC0・Three.jsのMIT表記を保持。配信物にも利用素材の案内を同梱。

## P2Pオンライン襲撃（追補）

Cloudflare等の専用バックエンドを必須にせず、GitHub Pages上の3アプリからブラウザ標準WebRTCで接続するDEV基盤を追加しました。村長端末が参加コードを発行し、輪廻転焦プレイヤーと魔物プレイヤーが応答コードを返します。村長端末が位置・HP・Tidebreak戦闘結果・襲撃台帳の正本です。

- 魔物と人間プレイヤーが接近すると、村長端末上のTidebreak共通ランタイムで自動戦闘を開始します。
- 魔物の安定player IDとcanonical village IDの組を入村時に台帳へ先書きし、切断・敗北・勝利後も同じ村への再入場を拒否します。
- 外部シグナリングサービスは使わずコード交換式です。STUNは接続経路の確立だけに使い、ゲーム状態や台帳を保存しません。
- 専用サーバーなしのため、村長端末がオフラインなら参加できません。これは村長端末Primary Host仕様と一致します。

## 正式サービス前に残るオンライン要件

| 要件 | 現状と必要な接続 |
| --- | --- |
| 正式アカウント連携 | DEVでは端末生成player ID。正式認証済みID・死亡/転生規則との接続が必要 |
| 正式な共有ハウジング正本 | DEVでは現行foundation村。ハウジング本編の保存形式が統合された後、そのcanonical village IDと配置へ接続する |
| 不正耐性のある再入場禁止 | 村長端末の永続台帳では成立。ブラウザデータ削除・村長端末交換にも耐える正式サービスでは署名済みIDまたは共有台帳が必要 |
| Host切断・Migration | このPRでは未実装。村長端末ホストWORKの正規プロトコルへ合わせる |

既存配信はGitHub Pagesのままです。P2P DEVはサーバープロセス・秘密情報なしで実通信します。正式サービス用の認証や共有DBが稼働したという意味ではありません。

次の接続では、まず認証と村ホストのDEVエンドポイントを確定し、入場時にサーバー台帳をatomic確定してからセッションを開始します。再送はidempotency keyで同じ結果へ収束させ、切断・敗北・転生・村改築でも台帳を削除しません。クライアント申告のaccount、勝敗、捕食報酬をそのまま確定しません。建物・家具を永久削除する変更は含めません。
