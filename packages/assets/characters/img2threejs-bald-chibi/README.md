# Front-reference chibi reconstruction

The source is the attached **character** image (`reference.jpg`, 1024 × 1536); the unrelated Actions infographic was excluded. The external toolchain is checked out at `img2threejs/img2threejs@6e60b5e22419464b4853e01ddb6c0e6f6659a733` (Apache-2.0). `reconstruction-spec.json` records measured image landmarks, model dimensions, inferred regions, projection choice, and executed commands.

From the game repository root, run `python3 packages/assets/characters/img2threejs-bald-chibi/bake-head.py packages/assets/characters/img2threejs-bald-chibi/reference-delit.png apps/character-studio/public/img2threejs-bald-chibi/head-uv.png`. The checked-in image is the result of the actual per-pixel orthographic UV sampling. The upstream `forge/stage3_build/bake_projected_texture.py` emits **only a descriptor**, as its own help text states. `projection-plan.json` is that descriptor, and `camera-observation.json` is a heuristic frontal camera from `solve_camera_pose.py`; neither is an image bake or a calibrated camera. The custom rasterization is documented in `bake-head.py`.

The model is independent of the game in `apps/character-studio/src/img2threejs-bald-chibi.js`. Its comparison/turntable page is `apps/character-studio/img2threejs-preview.html`; the character catalog adds the same model as a selectable source while leaving existing KayKit/GLB choices intact. Full ellipsoids, a closed front/back torso loft and rounded tapered limbs supply real volume. The head's estimated depth/width ratio is 0.804. Hair is absent in the supplied character reference. The profile, back and sagittal limb volumes are inferences from the only observed front image.

The upstream starter spec was generated with `new_pre_spec_assessment.py` and `new_sculpt_spec.py`, then checked with `validate_sculpt_spec.py`. Its generic character template introduced hair and adult-like assumptions absent from this image; its **strict-quality gate did not pass**. The measured reconstruction spec here is an explicit adaptation and does not claim upstream pipeline completion. Browser evidence must confirm front, both sides, back, rotation and the selection canvas before this should be called finished.

## Visual review

The checked-in `review/` images are actual Chromium WebGL screenshots of the standalone preview and character-studio selection canvas. `comparison-front.png` shows the front reference alongside the model; `standalone-{front,right,back,left,three-quarter}.png` cover the full volume; `selection-{front,side}.png` confirm the visible catalog model. The focused browser scenario checks `window.masterCharacterReview.audit.modelId`, visible actor state and absence of page errors. Local Chromium used software WebGL and the same model source bytes as the candidate PR. It found 38 mesh components and head depth/width 0.804.

Corrections from the first capture: rounded the previously angular torso and limb seams, enlarged the head, intersected the ears with the skull, built two rounded shorts shells with a crotch arch, softened the cloth shade, reduced the foot beads and widened only the new model's studio camera framing. The remaining likeness gap is visible in the comparison: the sculpted face volume, ears, fabric folds, hands and feet remain approximate. The profile and back are inferred; they are not validated against a second reference image.
