# First-build director review acceptance

ユーザー依頼: 3アプリのディレクターレビュー改善を実装し、DEV公開まで確認する。

- 初回テントで配置可能候補を提案する。world.canPlaceをそのまま用い、資源・入口・衝突・寝床予算は緩めない。候補の選択だけでは建築しない。
- 既存の完了操作を維持し、valid/invalidに応じて「ここに建てる」等の結果が分かる文言を表示。
- 建築確定後は実際の寝床増加を短く通知。保存失敗を保存成功と表示しない。
- 設定と配置補助のタッチ領域を44pxへ。見た目の絵柄やゲーム規則は変えない。
- 通常UIによるテント選択・配置補助・確定・再読込保持と、既存建物の内装に家具を1つ配置して保持を検証。state注入や既存物削除はしない。

PR #90の大きな内装競合整理・施設ビジュアル・住民カメラとは作業境界を分け、branchを上書きしない。#90に共有済み。
main / Productionは変更しない。Ready後は既存IntegrationでDEV公開を確認する。

## First-run autoplay tutorial acceptance

初めて村を開始したユーザーに、説明文だけではなく実際の村の画面上で「何もないところから暮らしが立ち上がる」導入シーケンスを自動再生する。

- 保存データが存在しない初回起動だけ自動再生し、既存セーブ・再訪では勝手に再生しない。
- 正規の初期world/saveを壊さず、村長宅・焚き火・護衛宅を一度見えない状態から順番に出現させ、カメラ移動と配置ゴーストで「建物は場所を決めて置く」操作を見せる。
- 導入中も保存データの正当性を維持し、途中で閉じても次回ロード不能な中間stateを残さない。
- 導入UIはゲーム画面を主役にし、短い説明、進行表示、スキップだけに限定する。スマホでスクロールを要求しない。
- 各ステップで「つくる」「場所を決める」「施設ごとに役割がある」を視覚的に伝え、最後は既存の通常チュートリアルへ自然に引き渡す。
- 導入済みフラグはセーブに保持し、再生完了・スキップのどちらでも再訪時の自動再生を止める。デバッグ/QA用の明示的な再生入口は通常導線へ露出させない。
- main / Productionは変更しない。Ready後のCI・Integration・DEV公開は既存Integrationへhandoffする。
