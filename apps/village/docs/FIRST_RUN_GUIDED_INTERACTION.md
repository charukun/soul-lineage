# First-run guided interaction

村の初期化直後にだけ走る導入は、完成済み施設を自動上映する演出ではなく、通常プレイと同じ入力経路を学べる対話型チュートリアルとする。

## 受入条件

- UI は通常の村UIと同じ素材感・輪郭・タイポグラフィを使い、汎用的なフラットモーダルを重ねない。
- 一度に教える操作は1つだけにし、読み取り時間を確保する。時間経過だけで次の操作へ自動進行しない。
- `つくる`、カタログ選択、1本指ドラッグ、短いタップ確定の順に、通常プレイと同じDOM / pointer入力経路を通す。
- 指のデモは実際のタップ／ドラッグ軌跡と同じ位置・速度で表示し、単なる状態変更の代用品にしない。
- デモ後はユーザー本人の同じ操作を待ち、成立した入力を観測してから次へ進む。
- チュートリアルが直接 `world.add` / `world.move` / `commitPlacement` を呼んで建築を成立させない。
- 誤操作は破綻扱いにせず、その場でヒントを再提示する。操作不能な全面ブロックを避ける。
- `もう一度見る` と `スキップ` を用意する。Escapeでも安全に終了できる。
- 小さい画面、safe-area、横向き、`prefers-reduced-motion` で操作対象や説明が隠れない。
- 完了／スキップ状態は保存し、中断した場合は安全に再開できる。
- タイトル画面の「村を初期化」で現在の村を退避・初期化した場合は、次の入村で初回チュートリアルを再び開始する。
- 上記のタイトル初期化経路は、保存状態だけの単体テストではなく、実ブラウザで「タイトル → 村を初期化 → 再読込 → 村へ入る」まで操作し、チュートリアルUIの再表示を確認する回帰テストで固定する。

## Quality pass

初回チュートリアルの品質改善は、情報を足すのではなくゲーム画面へ注意を戻す方向で行う。

1. 操作ステップの本文は原則1文に短縮し、操作名を見出し、意味の補足を本文へ分離する。
2. welcome / done は中央の導入カード、build / catalog / drag / place は上部の薄い案内札として扱い、プレイ領域を覆いすぎない。
3. 現在の進行を `1 / 4` の数値と細い進行線で読めるようにし、装飾だけの小さなマーカーへ依存しない。
4. 操作成功直後は短い「できた」状態を返し、次の操作へ切り替わったことを視覚的に伝える。自動で操作そのものを代行しない。
5. タップ対象・デモ指・案内札の視線誘導を一つの階層に揃え、同時に複数箇所を強調しない。
6. 390×844 と 320×844 では主要ボタンを44px相当以上に保ち、ガイド本文・対象・主要操作が同時に画面内へ収まること。
7. `prefers-reduced-motion` では情報構造を維持したまま、指の移動・脈動・成功アニメーションを省略する。

## Mobile screenshot correction

実機スクリーンショットで操作中の案内札と配置UIが縦方向に競合し、補助操作が主操作より強く見える場合は、次を優先して修正する。

1. `drag` / `place` では案内札の縦寸法を抑え、配置ツール群との間に明確な空間を残す。補助ボタンは本文と同じ視線階層へ置かない。
2. `もう一度見る` は常時の大きなボタンにせず、補助的なテキスト操作または小型コントロールとして扱う。
3. 人体の一部を模した自作の指形状は使わない。タップは中立的な円形タッチカーソル、ドラッグは同カーソルと軌跡で示す。
4. タッチデモは一瞬だけ表示して消さず、操作を待っている間は読み取れる長さで表示し、適度な間隔で自動再演する。
5. タップデモは接触点を最低1秒程度認識できる時間構成にし、ドラッグは開始点・移動・終点が追える速度にする。
6. 画面内でチュートリアル案内、配置操作、タッチデモの3要素が重ならないことを、390×844と狭幅モバイルで確認する。

## QA

1. 新規村、またはタイトル画面の「村を初期化」直後の村で開始すること。
2. `つくる` を実際にタップするまでカタログ説明へ進まないこと。
3. カタログ項目を実際にタップするまで配置説明へ進まないこと。
4. 配置中の1本指ドラッグを観測するまで確定説明へ進まないこと。
5. 短いタップで通常の配置処理が成立した後に完了へ進むこと。
6. チュートリアル側から建築状態を直接書き換えないこと。
7. Pixel Fold級の狭い幅と低い高さでも説明と操作対象が同時に見えること。
8. 一度チュートリアルを完了／スキップ済みの保存でも、タイトルから「村を初期化」した後は再表示されること。
9. 実ブラウザ回帰ではタイトルの初期化ボタンを実際に押し、再読込後の入村でガイドが表示されることをDOM可視性まで確認すること。
10. 操作ステップでは中央のwelcomeカードを残さず、案内札がゲーム画面の主要入力領域を過度に覆わないこと。
11. 390×844 と 320×844 の両方でガイドの主要ボタンが44px相当以上かつviewport内にあること。
12. `drag` / `place` では案内札と配置ツール群が重ならず、タッチカーソルが主操作領域で1秒以上認識可能なデモになること。
13. `もう一度見る` が主操作より強く見えず、円形タッチカーソルが人体形状に見えないこと。
