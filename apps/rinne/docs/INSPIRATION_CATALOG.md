# 閃き・技モーション共通カタログ

輪廻転焦の「閃き」は特定の戦闘デモや実行ランタイムに所有させない。基礎動作、武器別の候補集合、閃き生成に必要なメタデータを共有packageの正本として管理し、各戦闘ランタイム、Visual Review Lab、技作成UIはその正本を利用する。

## 所有境界

- 正本は共有packageに置く。`apps/rinne` や `packages/tidebreak-combat` は候補集合を独自定義しない。
- Tidebreakは自動戦闘の実行器であり、閃き候補の所有者ではない。
- 共有packageはappをimportしない。描画、DOM、Three.js runtime、ダメージ計算、AI、入力処理は含めない。
- 既存の武器別候補、レアリティ、足運びなどの意味を移設時に変更しない。まず所有境界だけを正す。

## 正本が表すもの

最低限、武器ごとの `open / middle / finish` 候補と表示用 `tag / desc`、基礎動作の識別子を共有する。片手剣、大剣、槍、斧、拳、刀など、現在の閃き対象を欠落させない。

候補配列内の同一ID反復は、既存抽選で明示的なウェイトとして使われていた場合だけ維持する。例として槍の `open` にある `thrust` の反復は移設時に勝手に正規化しない。一方、全体の基礎動作ID集合は一意な集合として公開する。

技は共有候補から1〜3個の基礎動作を構成し、序・破・急へ配置して使用できる。自動戦闘や演舞専用の別名技を正本として増殖させず、同じ基礎動作IDを共有する。

## 実行側の責務

- Tidebreakは共有カタログを読み、既存の `STRIKES`、当たり判定、間合い、AI、属性、足運び、溜め、序破急の実行ロジックへ接続する。
- Visual Review Labは同じ基礎動作IDをレビュー対象へ対応付ける。レビュー専用の候補集合をゲーム仕様の正本にしない。
- Storyで習得する技や保存済み技は共有基礎動作IDを参照できる。物語固有の習得条件や名称は各ドメインに残してよい。

## 受入条件

1. Tidebreak内部から武器別閃き候補の正本定義を除去し、共有packageをimportする。
2. 片手剣、大剣、槍、斧、拳、刀の既存候補集合と既存の明示的ウェイトが移設前後で欠落しない。
3. 閃き生成と自動戦闘の既存結果範囲を維持し、Tidebreak固有の9技などへ縮退しない。
4. 共有カタログがブラウザAPI、renderer、appコードへ依存しない。
5. 共有package単体テストで武器集合、必須フィールド、ウェイト互換、全体ID一意性、既存代表技を検証する。
6. Tidebreak側テストで共有カタログ由来の候補が実際の生成・戦闘経路に使われることを検証する。

## 本編の生活・修行・危険循環

輪廻転焦本編では、閃きを戦闘だけの報酬にせず、村での生活、建物内の環境、ハウジング設備、修行、村外の危険を一つの成長循環として扱う。

- 建物へ入り、その建物に実際に置かれている家具・道具・設備の特性へ一定時間触れることで、関連する非攻撃系スキルを閃ける。建物種別そのものではなく、設置物の特性を主要入力とする。
- 非攻撃系の閃きは攻撃技より高頻度にし、観察、呼吸、足運び、受け身、集中、危険察知、体幹、反復、距離感覚、環境適応など、後続のアクション系閃き率や生存率へ影響する補助スキルを十分な種類用意する。
- 補助スキルは「次に特定カテゴリのアクション系スキルを閃きやすくする」「修行時の試行回数や学習効率を上げる」「被弾や致命傷の発生率を下げる」「一撃の火力や間合いを伸ばす」など、ビルド差が体感できる効果を持てる。
- かかし修行は村生活から自然に到達できる主要導線とし、初期村では見つけにくい裏機能にしない。村の生活導線、稽古場、衛兵や住民の行動、状態変化の短い演出から修行場所の存在を理解できること。
- かかしでは単なる攻撃回数稼ぎではなく、現在の補助スキル、装備、姿勢、距離、反復回数を入力に、関連アクションの閃き候補と成功率が変わる。
- 村外では衛兵とモンスター・野生動物が同一時間軸上で継続的に交戦し、村境界が静止した待機空間にならない。常時戦闘の密度は村アプリ側の生活simulationを壊さず、本編側で必要な危険・演出・戦闘参加だけを扱う。
- 序盤から死亡し得る高致死率を許容する。ただし死因が無作為に見えないよう、危険察知、回避的な足運び、受け、体力、防具、距離、火力、先制など複数のスキル構成で致死率や戦闘時間を変えられること。
- 基本ゲームフローとして「村で生活する → 建物と設置物から補助スキルを閃く → かかしで修行する → アクション系へ派生する → 村外の戦闘へ関わる → 生還または死亡する → 次の選択へ進む」が短時間で一巡できること。

### 本編受入条件

1. 発展済みの出生村に複数の入室可能建物と、閃きへ寄与する複数カテゴリの設置物がある。
2. 非攻撃系スキルの候補数が攻撃系より多く、複数の補助スキルがアクション系閃き確率・修行効率・生存性・火力へ実際に寄与する。
3. かかしへ到達して修行を開始するまでの導線が通常プレイ中に理解でき、隠し操作や長い説明文へ依存しない。
4. 村外で衛兵と敵性生物の戦闘が継続し、プレイヤーが介入・離脱・死亡できる。
5. 初期構成でも死亡し得る一方、異なる補助スキル構成で致死率や戦闘結果に明確な差が出る。
6. 既存の村アプリとの境界、共有package所有、Platform分離、HUD説明集約を壊さない。
