# 友達とのDEV試遊

## RRP履歴確定の組み込み範囲

本編の20Hz進行と保存待ちを分離し、出生・寿命終了・転生は確定済み履歴を基準に配信する。操作IDによる重複拒否、保存応答消失からの再照会、旧Epochの書込み拒否、checkpointと履歴の復旧barrierを導入する。検証条件は遅い保存中も他の人物が動くこと、未確定の転生を配信しないこと、同じ要求の再送で世代が二重に進まないこと、保存失敗時に闇になり確定済み履歴を巻き戻さないこと。

初期adapterは既存Webの端末保存。クラウド正史・端末消失への耐久性・別Hostへの自動Migration・敵対Hostへの安全性をローカル保存で代用したとは扱わない。これらに必要な外部権限/履歴サービスへの接続は別adapterの契約とする。新しい課金サービス、ゲームの寿命/救助/転生ルール、ソロ保存、他アプリ、main/Productionは変更しない。

対象は現在の `100年人生` 本編。タイトルの「友達と遊ぶ」から、同じ村と前線をプレイする。従来の別パネルによる見学や外部Reality Labとは別の、本編への接続。

## 友達に渡す手順

Integrationでこの変更がDEVへ公開された後、全員が [輪廻転焦DEV](https://charukun.github.io/soul-lineage/dev/rinne/) を再読み込みし、タイトル右下の版が同じことを確認する。

1. 開く人は「友達と遊ぶ」→「村を開く」。本編に入ったら「友達」→「友達を招く」。招待リンクをコピーまたは共有する。
2. 友達はリンクを開き、「この招待で参加」→「返事をコピー」。返事を村を開いた人へ渡す。
3. 開いた人は返事を貼り、「届いた返事を受け取る」。つながると友達も本編へ入る。
4. 同じ場所で互いの姿と移動を確認する。世界時計の倍率は開いた人が操作する。成長、武具選択、出航、同じ前線の敵のHPを共有する。
5. 追加の友達には1人ずつ新しい招待を作る。招待は15分、同時に準備できる返事待ちは1件。開いた人は試遊中、その画面を前面に保つ。
6. 開いた人の画面を閉じると、友達側は闇になって進行を止める。開いた人が同じ端末・ブラウザで「前の村を開く」を選び、新しい招待と返事を交換すると、友達は同じキャラクターで戻る。

直結できない回線では参加できない。現行の接続は既存STUNを使い、TURN認証・中継サービスは未構成。最初は同じWi-Fiなど直結できる組み合わせで動作確認し、別回線の結果を次の判断材料にする。長い招待/返事をメッセージアプリが途中で省略しないよう、全文をコピーする。

## 現在の意味と限界

- 30人分のキャラクターを保持する村。今回は2端末での試遊を入口にする。30人実機、Pixel Foldの負荷、WAN/NAT/TURN対応を確認済みとはしない。退出したキャラクターも村に残り、村が動いている間は成長・戦闘が続く。累計30キャラクターで満員になり、初期版には参加者削除UIがない。
- Hostが20Hzでゲームルールを処理する。Guestは移動と輪廻の意図を送り、Hostの約10Hzの結果を描画する。敵の時計とHPは前線ごとに1つ。攻撃の同時判定はキャラクターIDの固定順で、同じ敵の撃破報酬は最後の一撃に1回だけ与える。協力向け難易度や共有報酬の調整は未実施。
- 送る他者は同じ村/前線・60m以内の表示状態。相手の接続券や人生履歴は送らない。RRPの観測範囲・世界時計・Epoch・闇と再同期を本編へ接続する最初の段階であり、Causal Interest、Macro/Collapse、Cell Authority分散は未実装。
- 村を開いた友達を信頼するDEV。Guestの速度・入力順・接続先・版は検査するが、改造Host・端末保存改ざん・共謀・Sybilに対する安全性はない。
- 個人の `life-v2` とは別の `coop-v1:<worldId>` へ村を保存し、Guestは自分の再接続券を保存する。約1秒ごとの保存と出生/寿命/輪廻時の保存を使い、重要な保存が未完了ならその結果は配信しない。失敗したらHostの進行を止める。
- 保存はHost端末内。クラウド正史保存・絶対に巻き戻らない血統・別端末への引継ぎではない。突然終了で最後の未保存の移動や戦闘結果が戻る可能性がある。ブラウザデータ削除で村や再接続券を失う。
- Hostが非表示なら世界時計を止める。通信の無言停止はGuestが約2.5秒で検出して闇にする。別の人が独断で進行を引き継がず、同じHostが保存を読み直してEpochを増やす。これは自動Host Migrationや分断した2世界の合意ではない。
- reliable WebRTCで結果を送り、送信キューが増えたら古い表示の配信を省く。現時点で予測・補間・リレーはなく、遅延やジッタは操作と表示に現れる。出生中の移動は共有キャラクター位置を使い、ソロの自動抱っこ散策経路を共有シミュレーションしていない。

## 再現可能な確認

高速のゲーム/プロトコル検査:

```sh
node --test apps/rinne/tests/coop-world.test.mjs apps/rinne/tests/coop-session.test.mjs
```

実WebRTCプロトコルのローカル検査。開発用の別ディレクトリに `werift@0.24.4` を置き、アプリの依存や配布バンドルへ追加しない:

```sh
npm install --prefix /tmp/rinne-rtc-probe --no-package-lock --no-audit --no-fund werift@0.24.4
RINNE_RTC_MODULE=/tmp/rinne-rtc-probe/node_modules/werift node apps/rinne/tests/coop-rtc-probe.mjs
```

これはNode上の実SCTP/DTLS/ICE通信で、入村・移動・共通敵HP・停止・切断・同一Host復元・Epoch・キャラクター同一性を検査する。ブラウザ、WebGL、実機のNATやTURN検査の代わりにはならない。

既存Rinneブラウザgateの `rebuild-playthrough.browser.mjs` から `coop-play.browser.mjs` を呼ぶ。2つのブラウザcontextで招待UI、他者の移動、時計、Host消失、再接続、個人セーブ分離、退出後のソロ開始まで確認する。本実装環境のブラウザはローカルURLを `ERR_BLOCKED_BY_CLIENT` で拒否したため、この画面検査の実行結果はIntegration側で取得する。Node試験合格を画面検査合格と読み替えない。

DEVで友達と試した結果は「全員の版・端末/ブラウザ・Wi-Fi/携帯回線・人数・接続可否・闇から戻れたか・操作の遅れ」を添えて扱う。次の実装判断は、まず接続失敗ならTURN、接続できて遅いなら入力予測/帯域、人数増加でHost負荷が支配的ならCell分割・リレーの順で原因別に行う。
