# WORK DESK v0.1 — 登録台帳版

スマホで登録タスク・セッションの場所・報告された状態をまとめる、依存ライブラリなしの静的ページ。Viteのpublicコピーと既存DEV配信を使い、ゲームの実行コード・共有package・CI/CD・main/Productionは変更しない。

公開後のパスは `/soul-lineage/dev/rinne/work-desk/`。この記載自体は配信成功の証拠ではない。最終developのIntegration結果と実際の配信内容を確認する。

## 実装済み

- プロジェクト別の登録台帳、検索、状態別件数、非公開ChatGPT会話へのリンク。
- 依頼を未送信として保存し、コピー・ChatGPTでの手動送信へ引き継ぐ。送信済みの明示記録だけを依頼済みとし、実行開始とは扱わない。
- 手動またはWORK報告JSONによる状態反映。確認時刻・情報源を表示。1時間超の作業中報告は更新待ちとして扱い、停止と推定しない。
- JSONバックアップとChatGPT書き出しのconversations.jsonのメタデータ取り込み。本文・認証情報は保存しない。履歴の更新時刻から実行状態を推測しない。
- 公開リポジトリ charukun/soul-lineage のOpen PRと明示的なintegration/develop statusの読み取り。通常CI成功をIntegration成功と取り違えない。100件を超える場合は部分取得と表示。
- 保存失敗・壊れた保存データ・別タブの更新競合を検出。CSPハッシュ検証、URL制限、HTMLエスケープ。

## 元の依頼に対する未完了範囲

これはChatGPTアカウント全体のライブ管理コンソールではない。全セッションの自動列挙、プロジェクト所属の自動取得、WORKの実行状態・heartbeatの直接取得、既存WORKへの直接送信・起動・中断、端末間同期は未実装。利用可能な公式仕様・接続では、この個人アカウントの全セッションを取得・操作する経路を確認できていない。一般のOpenAI API会話を個人ChatGPTの既存会話と同一視しない。

画面の件数は登録台帳の件数だけで、アカウント全体の件数ではない。初回は0件であり、ユーザーの既存作業が0件という意味ではない。ユーザーの会話データを公開ソースに埋め込まない。Codexの場所ラベルは手動分類であり、Codexセッション接続を意味しない。

## データ・費用

localStorageは当該ブラウザ・origin単位。サーバーへ台帳を送信せず、AI API呼び出し、常駐サーバー、定期polling、追加課金サービスを用いない。GitHubの公開APIは5分キャッシュ・連続取得制限・エラー表示付き。無料枠や契約条件の変更まで保証するものではない。

同じoriginのコードや端末利用者から隔離された暗号化保管庫ではない。秘密情報を入力しない。ブラウザデータを消すと台帳も消える。JSONバックアップは平文であり、他人へ公開しない。ホーム画面用manifestはあるが、Service Worker・オフライン起動保証はない。

## 検証

`node --test apps/rinne/tests/work-desk.test.mjs` の10テストをローカルで実行・成功。HTML内JavaScriptの `node --check` も成功。

追加のChromium検証では、作成したHTMLをset_contentで描画し、30項目の登録・依頼下書き・報告・履歴メタデータ取り込み・重複防止・保存障害・URL安全性・360/412/844/1280pxレイアウト等を確認した。この環境では通常のブラウザ遷移が管理ポリシーで禁止されており、その制限を解除せず、storage・clipboard・download・GitHub応答を模擬した。公開URLの実通信、実永続化、実Pixel Fold検証の代わりではない。

作業環境から最新repoを通常cloneできなかったため、ローカルの全repo高速検証は未実施。既存CIの正規fast gateとIntegrationを必須とし、緑の状態を手で作らない。公開後の既存ゲームbrowser gateは、この独立ページの操作検証を自動的に証明するものではない。

インラインscript/style変更時はContent-Security-Policyのsha256を必ず再生成する。public配信により内容はそのままコピーされる。
