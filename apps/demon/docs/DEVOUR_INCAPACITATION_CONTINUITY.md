# 尽喰廻遊: 戦闘不能 → 捕食の演出連続性

## 目的

戦闘で人間が戦闘不能になった瞬間から捕食完了までを、一つの身体状態の連続として見せる。捕食だけを派手にして戦闘不能姿勢と切断せず、Tidebreak の打点・damage・world 座標・捕食成立時刻・報酬規則は変更しない。

## 受入条件

- 戦闘不能は一フレームで横倒しへ飛ばず、直前の戦闘姿勢から短い presentation-only の崩れへ遷移する。
- 致命打直後は直前の戦闘姿勢を起点に、`impact → buckle → drop → contact → settle` の全身5段階で約0.68秒かけて戦闘不能姿勢へ移る。単一の root roll 補間だけで倒れたように見せない。
- `impact` では胸郭と頭が遅れて反応し、`buckle` では膝と腰が先に抜け、`drop` では骨盤・胸・肩・腕が時間差で落ち、`contact` では肩/腰の接地に小さな反動を持たせ、`settle` で首・手首・武器側の腕まで脱力する。
- 左右どちらへ崩れるかは表示上の安定した値で決め、全NPCが同一方向・同一シルエットで倒れ続けない。world座標や当たり判定は動かさない。
- 倒れた人間は武器・手足・首を脱力させ、捕食開始前と捕食開始直後で身体姿勢が不連続に跳ばない。
- 撃破直後に捕食クロックが始まっても、怪物の `lower / reach` 中は被捕食者の崩れを最後まで読ませる。表示上の引き寄せ・持ち上げは崩れの主要接地より前に開始しない。
- 捕食中の被捕食者は、怪物側の lower / reach / pull / bite / swallow / recover と同じ正規化進行値で引き寄せ・持ち上げ・噛み込み反応・嚥下方向の移動を行う。
- 捕食の二回の bite beat は、怪物の顎・被捕食者の身体反応・既存の音/光の山場を同じ時点へ揃える。
- 捕食を移動で中断した場合は `capturedBy` が解除され、報酬・成長演出を出さず、戦闘不能者は自然に地面の脱力姿勢へ戻る。
- 捕食成立直前に被捕食者が地面へ戻る、直立へ戻る、逆方向へ跳ねる挙動を出さない。成立時のみ既存 `consume` により非表示となる。
- 新規の露骨な流血・臓器表現は追加しない。魂・局所光・既存リング/粒子など非写実的な表現で密度を上げる。
- presentation-only の変更に留め、AI、hitbox、save/schema、捕食時間、移動入力、戦闘結果を変更しない。

## モーションの主要ポーズ

- 0.00: 致命打直前の戦闘姿勢を保持し、支持脚・武器腕・胸郭の方向を引き継ぐ。
- 0.12: impact。胸がわずかに反り、頭と腕は慣性で一拍遅れる。
- 0.34: buckle。腰が落ち、片膝が深く折れ、反対脚はまだ接地を支える。
- 0.62: drop。支持を失った骨盤から上体が横へ流れ、地面側の腕が遅れて出る。
- 0.82: contact。肩と腰が接地し、頭・前腕・武器腕に小さな遅延反動が出る。
- 1.00: settle。呼吸や戦闘姿勢へ戻らず、捕食対象として連続利用できる脱力姿勢に落ち着く。

## 捕食の接触・重量契約

捕食の説得力はエフェクト量ではなく、怪物と獲物の接触が画面上で成立し続けることを優先する。

- `reach` では手が獲物へ向かうだけで、獲物の重心は先に動かさない。手が上体・腰の接触点へ到達してから `pull` を開始する。
- `pull` では片手を上体、もう片手を腰側の拘束点として扱い、両手と獲物の接触点を同じ共有フレームから求める。手だけが空中を掴む、獲物だけが吸い寄せられる表現にしない。
- 獲物の持ち上げ量は怪物の現在の成長スケールに合わせる。小型時は地面近くで引きずる／低い部位へ噛みつき、大型時は上体を持ち上げて口元へ運ぶ。固定の高さで全サイズを処理しない。
- `bite` は獲物側の接触点が口元へ届いている時だけ見えるようにし、顎の閉じ、獲物の反応、局所光、bite ring、音を同じ beat に揃える。
- bite 中も両手の拘束を失わず、噛み込みの反動で怪物の胸・頭・腕と獲物の上体が逆方向へ小さく反応する。接触後に手が獲物を貫通したり離れたりしない。
- `swallow` では獲物の重心を怪物の胸側へ段階的に寄せ、全身縮小だけで消失を表現しない。成立直前まで手・口・獲物の位置関係を保ち、成立時のみ既存 `consume` で非表示にする。
- 魂粒子・wisp・bite ring の発生位置は、シミュレーション上の死体位置ではなく、現在画面上で拘束されている上体／口元の共有接触点を使う。
- Default monster と Silver Reaper の双方で同じ接触フレームを利用し、キャラクター差で獲物だけ別位置へ動く状態を作らない。

## 検証

`sampleDevourMotion` と被捕食者用の純粋なサンプラについて、0〜1 の全域で有限値・段階連続・戦闘不能5段階・左右差・bite beat・終端保持を局所テストする。捕食の共有接触フレームは、手の拘束点・口元・獲物上体の距離が `reach → pull → bite` で収束し、bite 中に接触が維持され、怪物サイズごとの持ち上げ方が有限であることを検証する。Three.js 側は既存の `feast.test.mjs` と対象 app の build/check を維持する。モーション品質は数値テストだけで合格扱いにせず、実描画を取得できた場合は1倍速で撃破直前 → 接地 → 掴み → 引き寄せ → bite → swallow の連続を確認する。重い全体 E2E は通常実装 WORK では要求しない。
